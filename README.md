# Cross-Tool AI Setup Blueprint

**一套技能和规则，多个 AI 工具共用。**

这是一份跨项目、跨 AI 工具的**一次性环境搭建图纸**。交给你已安装的 Agent，按计划建立 `~/.ai-global/` 共享目录，并接入各工具的入口与权限配置。

**它是造底座的图纸，不是底座本身，也不是多 Agent 调度平台。** 搭建完成后，日常工作不依赖本仓库。

## 适用场景

**适合谁：** 在**多个项目、多种 AI 工具**之间切换的个人开发者，也适合作为**团队约定的起点**。

**能力边界：** 不提供**统一账号、企业权限管控或跨电脑自动同步**。

**何时不需要：** 只有**单个工具、单个项目**时，未必需要额外这一层。

## 解决什么问题

| 痛点 | 初始化后建立的机制 |
|------|--------------------|
| 同一 skill 在多个项目/工具里拷贝了十几份，内容还各改各的（版本漂移） | 通用 skill 只保留一份；任意 Agent 修改后，其他 Agent 后续读取同一份 |
| 换 AI 工具后，之前攒的 skill/规则全丢了 | 各工具只放一个"指针"，真实内容在工具无关的公共目录 |
| 在任意目录开会话，找不到"某项目专属"的 skill | 全局指针内嵌"项目→路径→专属目录"速查表，任何目录都能定位 |
| 通用 skill 和项目专属 skill 混在一起 | 明确分层：通用框架进 `skills/`，项目专属进 `projects/<项目>/` |
| 相同目录和脚本在不同 AI 工具中反复申请权限 | 在客户端原生能力允许的范围内，持久配置访问和脚本执行权限 |
| 已注册项目不在共享目录内，仍被反复要求授权 | 确认注册范围后，将项目原路径纳入各工具的权限适配，不因位置不同重复征询 |

## 快速开始：先预览，再应用

准备一个已安装、已登录且能操作本地文件的 AI 工具，以及你想接入的项目名称、别名和路径。**首次可以只选一个项目、一个工具**，确认有效后再扩展。

1. 获取图纸。克隆只下载本仓库，不会执行初始化：

   ```bash
   git clone https://github.com/lxch183/cross-tool-ai-setup-blueprint.git
   cd cross-tool-ai-setup-blueprint
   ```

   国内网络可改用 Gitee 镜像：`git clone https://gitee.com/lxch183/cross-tool-ai-setup-blueprint.git`（内容与 GitHub 同步）。

2. 在该目录启动 Agent，发送这段话：

   ```text
   请读取 INIT.md，先做只读预览，不修改配置、不执行初始化。
   确认我要接入的项目和工具后，列出：
   要新增或修改的文件、访问和执行权限范围、
   已知限制、备份位置及撤销步骤。
   保留我的已有脚本和项目位置，等我确认方案后再应用。
   ```

3. 审阅方案后，再让 Agent 应用。交付时应说明哪些能力已生效、哪些仅写入了配置，以及如何撤销；**有未完成项就保留为未完成，不把“文件已生成”当成“接入成功”。**

> 已有 `~/.ai-global/`？请说明是增量接入，先读取现有内容，不覆盖重建。初始化完成后，图纸可以归档；新增项目或工具使用共享目录内的运行期说明，不必重新克隆或初始化。

## 使用前的常见顾虑

| 你关心的问题 | 图纸规定的做法 |
|-------------|----------------|
| 会不会直接改我的环境？ | **先只读预览**：列出要改的文件和权限范围，经你确认后再应用。 |
| 要搬项目、重建工作区吗？ | **不需要**：已有项目、脚本原地保留，不创建额外工作区；迁移技能是单独选择的可选项。 |
| 会不会覆盖原来的配置？ | **先备份，再合并**：保留无关设置和拒绝规则，记录本次新增与修改的内容。 |
| 会不会把所有权限都放开？ | **按确认范围适配**：共享目录、已注册项目和明确的指针目标，不用全局关闭审批代替范围授权。 |
| 密钥、令牌和密码存在哪里？ | **存系统钥匙串，配置只存引用**：macOS 使用 Keychain，其他系统使用原生受保护凭据库，不把秘密值写进共享目录、脚本或 AI 记忆。 |

> 这些是执行图纸时必须遵守的流程，**不是仓库已经内置的自动保护或一键回滚功能**。当前交付的是可阅读的说明和模板，具体修改由你选择的 Agent 执行；应用前仍需审阅它给出的计划。

## 初始化会改哪些地方

| 位置 | 用途与修改方式 |
|------|----------------|
| `~/.ai-global/` | 保存入口、项目/工具注册表、共享技能、规则和辅助脚本；已有内容先读取、再合并。 |
| 各工具的全局指令文件 | 加入入口引用和速查信息，不复制整套技能正文。 |
| 各工具的原生权限配置 | 为确认过的路径适配读取、写入和脚本执行规则；可能涉及用户级配置或 hook。 |
| 系统钥匙串或受保护凭据库 | 仅在确需保存凭据时，按确认的服务和用途创建或更新条目；共享配置只记录条目引用。 |
| 项目目录 | 代码和已有脚本不搬动；项目级指针仅在选择该可选项后添加。 |

图纸本身不附带你的业务技能，也不承诺自动同步所有索引。首次搭建、后续变更都需要 Agent 按注册表维护；若生成同步脚本，应交付其用途、修改范围和使用方法。

**本地存放不等于离线运行。** AI 工具可能将读取的内容作为模型上下文发送给其服务商，技能和脚本也可能访问外部服务。请遵守所选工具的数据政策；不要把凭据、私人技能或公司项目配置提交到这个公开的图纸仓库。

需要持久化 API Key、访问令牌、密码等凭据时，使用系统钥匙串，由用户通过受保护的输入方式录入，脚本运行时按具体条目读取并直接用于授权用途，不回显给 Agent。系统凭据库不可用时明确报错，不退回明文文件。详见 [凭据存储规则](PERMISSIONS.md#凭据存储系统钥匙串)。

## 工具适配与已知边界

下面是已有入口模板和配置参考，**不是“所有版本、所有平台均已通过”的兼容性承诺**。具体机制见 [PERMISSIONS.md](PERMISSIONS.md)，原生资料链接在该文末。

| 工具 | 已有参考 | 必须区分的边界 |
|------|----------|----------------|
| Claude Code | 全局入口、目录与工具权限规则 | 文件访问和 Bash 执行分别配置，保留已有拒绝规则。 |
| Codex | 全局入口、文件系统权限、脚本命令规则 | 按版本选择配置格式，不能把命令前缀规则当文件路径 glob。 |
| Qoder | CLI 配置、IDE 入口与终端白名单参考 | CLI 与 IDE 分开；IDE 跨目录文件读写尚未完成通用验证，不能宣称已支持。 |
| GitHub Copilot | CLI hook、VS Code 与 JetBrains 配置参考 | 三种客户端分别适配；工作区信任不等于全部工具已批准。 |

现有权限记录主要来自 macOS 本机实践，不等于 Windows/Linux 或其他版本已确认可用。其他工具可增量接入，但可能需要补充原生适配，不能只改一条注册表记录。

减少重复批准是目标，**不是保证从此没有任何提示**。组织策略、原生安全检查、沙箱和高风险业务操作仍有各自的限制；允许执行某个脚本，也不意味着该脚本的所有行为都被限制在所在目录。

## 已有底座如何接入新 AI 工具

**最省事的做法：安装并登录新 AI 工具后，让一个已经接入底座的 Agent 帮它配置。** 新工具尚未配置入口和权限，由已接入的 Agent 完成接入，可避免一开始就找不到共享目录或被目录权限拦住。

以 Gemini CLI 为例：

1. 安装并登录 Gemini CLI。
2. 向已经接入底座的 Agent 发送下面的指令。
3. 配置完成后重新启动 Gemini CLI，确认它能读取底座入口、定位已注册项目，并使用共享技能和脚本。

可直接发送：

```text
请把 Gemini CLI 增量接入我现有的 AI 底座，不要重新初始化。

先读取 ~/.ai-global/ 下的 BOOTSTRAP.md、registry.json、
ai-tools-registry.json 和 PERMISSIONS.md。

先展示新增工具的配置变更、授权范围、备份及撤销方式，
等我确认方案后再应用。

在 Gemini CLI 的原生全局指令文件中加入底座入口指针，
保留原有内容，并更新 ~/.ai-global/ai-tools-registry.json。
按当前版本的原生机制，配置 ~/.ai-global/**、全部已注册项目
及指针目标的访问、写入和脚本执行权限。

如果现有权限同步脚本尚不支持 Gemini CLI，补充对应适配。
把确认过的配置方法写回本机 PERMISSIONS.md，
明确哪些已完成、哪些仍受客户端限制。

不复制 skill，不迁移已有脚本或项目，不创建额外工作区，
不改变其他工具的权限模式，不用全局关闭审批代替范围授权。
```

换成其他工具时，替换工具名称即可。完整接入包括 **入口指针、工具登记、权限适配**；只在注册表加一条或只生成指针，不算接入完成。

## 不用了，如何撤销

初始化时应交付每个变更文件的备份位置、变更摘要和撤销方式，不能只留一句“已备份”。

1. 按交付清单移除本次增加的入口引用、hook 和原生授权条目，保留原有配置。**只从注册表删除项目，并不会自动撤销工具权限。**
2. 文件在初始化后没有其他改动时，可恢复对应备份；已有后续改动时，按差异撤销本次新增部分，不整份覆盖。
3. 保留 `~/.ai-global/` 中的个人技能和脚本。清理生成文件前先确认已无工具引用，不递归删除整个共享目录。

目前没有统一的一键卸载器；撤销依赖实际交付的变更记录和各客户端的原生机制。
