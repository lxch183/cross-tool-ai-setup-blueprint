## 路由规则（读取，必须遵守）

用户提到某个项目/模块时，按上表"项目名/别名"匹配（忽略大小写）：
1. 命中后，到对应"代码路径"下工作；
2. 进入项目后，读 ~/.ai-global/projects/<项目>/skills/ 下的项目专属 skill、~/.ai-global/projects/<项目>/config/ 下的项目专属配置；
3. 匹配不到时，主动问用户是哪个项目，不要瞎猜。

## 共享目录与访问、执行权限

共享目录为 `~/.ai-global/`。所有实际接入工具记录在 `~/.ai-global/ai-tools-registry.json`，原生权限适配方法及本机配置位置见 `~/.ai-global/PERMISSIONS.md`。

- 共享目录、用户创建的辅助脚本、已注册项目、指针明确指向的文件/目录，均需对所有接入工具配置访问权限和脚本执行权限。
- 用户注册项目即将其 `code_path` 纳入上述范围，即使项目位于共享目录外，也不重复申请同一范围的授权。
- 按现有真实路径配置权限，不创建额外工作区、不要求切换工作区，也不为授权迁移已有脚本、skill 或项目。
- 新增项目时，同步项目注册表、本文件、各工具速查表和所有接入工具的权限配置；接入新工具时，覆盖全部既有范围。
- 新建辅助脚本时，支持目录范围的工具沿用已有配置；需要精确脚本规则的工具，由创建脚本的 Agent 同步补齐执行规则，不再逐个询问用户。
- 若已有范围仍被原生权限拦截，按权限指南定位缺失配置；不能仅凭文字声称已授权，也不能绕过组织策略或原生安全限制。

通用独立辅助脚本放入 `~/.ai-global/scripts/`，项目专属独立辅助脚本放入 `~/.ai-global/projects/<项目>/scripts/`。skill 自带脚本随 skill 存放，项目源码及随版本维护的构建脚本仍留在代码仓库。

## 凭据存储

需要持久化密钥、令牌、密码等凭据时，macOS 使用 Keychain（钥匙串），其他系统使用原生受保护凭据库；配置只保存服务名、账户别名或条目 ID 等引用，不保存秘密值。

- 通过系统界面或受保护的本地输入录入，不要求用户在对话中粘贴凭据，不将秘密值放入命令行参数。
- 不把凭据写入共享目录、项目配置、脚本、skill、日志、临时文件、AI 记忆或版本库。
- 本地脚本按需读取具体条目并在进程内存中使用，不把秘密值回显到工具输出或模型上下文。
- 目录与脚本授权不等于整库钥匙串授权；条目缺失、锁定、拒绝访问或后端不可用时明确报错，不回退到明文文件。
- 不擅自迁移、覆盖或删除已有凭据。完整规则见 `~/.ai-global/PERMISSIONS.md` 的“凭据存储”章节。

## 写入路由（反写规则/内容，必须遵守）

当用户让你"记住规则/写规则/更新规则/写 skill/记录内容"时，先判断归属，再写到正确位置。
「<项目>」的具体目录名见各工具全局指针里的速查表第三列。

### 第一步：判断归属
- 通用（跨项目）：规则与具体项目无关，任何项目都适用
- 项目专属：规则只对某个项目有效
- 无法确定归属时，反问用户（给出候选位置），不要自作主张

### 第二步：写到正确位置

| 内容归属 | 写入位置 |
|---------|---------|
| 通用规则（跨项目） | ~/.ai-global/rules/<名字>.md |
| 通用 skill（跨项目） | ~/.ai-global/skills/<名字>/SKILL.md |
| 通用独立辅助脚本 | ~/.ai-global/scripts/<名字>.py 或 .sh |
| 项目专属 skill | ~/.ai-global/projects/<项目>/skills/<名字>/SKILL.md |
| 项目专属独立辅助脚本 | ~/.ai-global/projects/<项目>/scripts/<名字>.py 或 .sh |
| 项目专属规则/配置 | ~/.ai-global/projects/<项目>/config/<名字>.md 或 .yaml |
| 项目清单/别名变更 | ~/.ai-global/registry.json + 本文件 + 各工具指针速查表；范围变化时同步各工具权限配置 |

### 禁止项
- 不把真实规则或 skill 正文写进各工具指针；索引变更时仅同步引用和速查表
- 公共内容不写项目目录，项目内容不写公共目录
- 同一内容不写多份
- 归属不确定时不猜，先反问用户
